# Implementation and verification checklist

The local RTX 4050 is the target for generated-data smoke tests. The user will run the full experiments on an RTX 4500 Ada with 24 GB of memory. The checklist records planned work. Verification results belong in the work log.

| Order | Change | Acceptance check |
| --- | --- | --- |
| 1 | Freeze one episode partition per dataset independently of base-training seeds. Record dataset and checkpoint identities, training and split seeds, eligible counts, action/state coverage and the effective SIGReg weight. Expose the upstream `loss.sigreg.weight` override with distinct checkpoint paths. | Identical dataset and split seeds reproduce all five episode roles across base seeds. No role overlaps. Record which checkpoint epoch was used. Verify the default 0.09 and sweep values 0.009 and 0.45 in resolved training configurations. |
| 2 | Fit each fresh prediction head with the same number of updates, draws and full/partial batch sizes. Record member seed, bootstrap sample, training loss and held-out error. Use the eligible training action rows and existing scaler for an action-vector kNN bank. Fit the current-observation kNN scale on the last available input frame. | Vary episode lengths in the regression check. Equal exposure counts survive unequal episode lengths. Calibration and test actions never enter either bank. The observation available at scoring time excludes the future target. |
| 3 | Use the same deterministic tint, distractor and occluder in offline and planning paths. Save per-clip case IDs, condition, scores, errors, action magnitudes and sample images. Record patch coverage and task-critical overlap where observed. Record normalized probe units and clean held-out quality. | Each altered history has the same case ID, underlying state and clean next target. Offline forecasts have no goal image. Use observation-only, observation-plus-goal and goal-only modes in closed-loop planning. Preserve existing tint commands. |
| 4 | Trace the selected plan, physical state and command exposure at actual execution. Compute the maximum of normalized forecast ensemble disagreement and current-observation kNN. Calibrate the initial threshold on clean, separate threshold episodes using the selected policy. | The current observation cannot change CEM candidate rankings. A threshold artifact can be consumed only by its matching model, fit and planning protocol. Keep each warning component and its timestamp. |
| 5 | Gate once before the first simulator action. Intersect acceptance with the evaluator’s active mask at the environment step boundary. Record each accepted case’s actual actions and termination, and each rejection as a separate decision with a null outcome. | Mixed, all-accepted and all-rejected vector batches execute the right number of real actions. An all-rejected batch gives zero coverage and null conditional success. Exclude synthetic control-flow truncation from physical events. Keep rejected and completed slots out of subsequent warning/exposure records. |
| 6 | Produce case-paired planning, offline episode-cluster and training-seed analyses. Score independently trained encoders on identical candidate sequences in terms of ID-normalized scalar goal cost. Generate figures from exported records and record runtime and memory. | Repeated windows stay with their episode. Shared test episodes stay paired across base seeds. Withhold training-seed intervals for unverified or insufficient independent seeds. Keep actual gate outcomes apart from complete ungated counterfactual outcomes. |
| 7 | Run unit tests, reapply the source adapter twice against the pinned upstream checkout and compare, then run the generated PushT workflow through training/fitting, scoring, threshold calibration, closed-loop gating and reports. | Record commands, outputs, hardware, failures and exact limits. Review the complete diff before the dated commit and verify the pushed commit against the remote branch. |

## Full experiments on the RTX 4500 Ada

Verify the datasets and released checkpoints, then run the official PushT, Reacher and Cube baselines. Time a real batch and complete a restricted PushT pilot before freezing the protocol. Use three independent base-training seeds for the primary PushT/Reacher comparisons, with the same split and checkpoint across shift families within each seed. Run the matched SIGReg and independent-encoder controls and the targeted Cube study. Determine from task semantics and recorded outcomes whether any Cube failure event supports a physical lead-time claim. Report time to budget exhaustion separately. Final H1–H4 conclusions require these research outputs.
